# Решения и допущения

Формат: решение — альтернативы — причина.

## Технологии

1. **Laravel 12, а не 13.** Альтернатива: свежий Laravel 13. Причина: ТЗ называет 11/12, а Breeze и Livewire 3 гарантированно поддерживают 12.
2. **Blade + Livewire 3 + Alpine + Tailwind 3 + Chart.js** (по умолчанию из ТЗ). Альтернатива: Vue + Inertia. Веских причин для SPA нет: ввод подходов без перезагрузки решает Livewire, таймеры — Alpine на клиенте.
3. **Alpine берём из бандла Livewire**, из `app.js` он убран. Иначе на странице два экземпляра Alpine и конфликт.
4. **Без Redis.** Сессии, кеш и очереди — драйвер `database` (по умолчанию в Laravel 12). Нагрузки, оправдывающей Redis, у дневника одного пользователя нет.
5. **Сервис `node` собирает фронтенд и завершается**, а не держит Vite dev-сервер. Так приложение работает сразу после `up` без лишнего процесса; для разработки фронтенда можно запустить `npm run dev` локально.
6. **Одна команда настройки `app-setup`** внутри контейнера: composer install, ключ, ожидание базы, миграции, сидеры, ожидание сборки. Код монтируется в контейнер, поэтому `vendor` ставится при настройке, а не в образе.
7. **Breeze (Blade, тёмная тема, Pest)** с переводом текстов на русский через `lang/ru.json` и собственный `lang/ru/validation.php` (без пакета laravel-lang, чтобы не тянуть зависимость ради нескольких строк).

## Данные

8. **Мышцы — таблица `muscles` + связи с ролью (primary/secondary)**, а паттерны, снаряды и типы — строки, проверяемые по `config/training.php`. Альтернатива: всё в JSON-колонках или всё в таблицах. Мышцы участвуют в связях и фильтрах (внешние ключи нужны), а паттерны — короткий фиксированный словарь, редактировать его через БД не требуется.
9. **11 групп мышц** как в ТЗ: «спина» не делится на широчайшие/трапеции, «плечи» — на пучки. Задняя дельта выделена паттерном `rear_delt`, средняя — `shoulder_abduction`. Проще для пользователя, достаточно для правил объёма.
10. **Обязательные паттерны шаблона — JSON-массив**, целевые мышцы — связь `day_template_muscle`.
11. **Стандартные шаблоны и упражнения имеют `user_id = NULL`**, пользовательские — свой `user_id`. Стандартные шаблоны не редактируются, но копируются в свои.
12. **Личные рекорды не хранятся**, а вычисляются из истории. Нет риска рассинхронизации при правке подходов; объём данных одного человека небольшой.
13. **При завершении тренировки упражнения без подходов удаляются** — они не выполнялись и не должны влиять на ротацию и аналитику.
14. **Дата тренировки хранится как чистая дата** (мутатор), чтобы сравнения работали и в PostgreSQL, и в SQLite (тесты).
15. **Вес в гравитроне — противовес** (меньше = тяжелее). Список таких упражнений в `training.assisted_exercises`; прогрессия для них предлагает уменьшить противовес, разминочные проценты не считаются.
16. **Упражнения с собственным весом**: вес — дополнительное отягощение (0 без него).

## Правила подбора (`ExerciseRecommender`)

17. **Кандидаты** — упражнения, у которых основная мышца входит в мышцы дня. Без шаблона мышцы дня — основные мышцы уже выбранных упражнений, а если ничего не выбрано — все группы.
18. **Ранжирование — сумма очков** с весами из `training.scoring`: незакрытый обязательный паттерн (+100), новый паттерн (+30), ненагруженная мышца (+40) или ниже минимума за тренировку (+20), базовое (+25), недобор за неделю (+15), «свежесть» до +10 (1 очко за 3 дня без упражнения, никогда не выполнялось = +10), штраф за утомляемость, когда до конца бюджета меньше 10 минут. Каждое начисление добавляет текстовую причину.
19. **Подсказки сгруппированы по паттернам**: сначала незакрытые обязательные в порядке шаблона, затем по лучшему баллу. В группе показываются 3 лучших, остальные — по кнопке «Ещё варианты».
20. **Жёсткие исключения** (с причиной в списке «Почему не предложены другие»): лимит упражнений на мышцу за тренировку (по умолчанию 3), превышение недельного максимума подходов (16), выход за бюджет времени, ротация.
21. **Ротация** смотрит на последние N завершённых тренировок, где мышца была основной (N = 3). Если из-за ротации обязательный паттерн нечем закрыть, по умолчанию предлагается вариант, выполнявшийся давнее остальных, с пометкой. Это спорное правило — выключается в настройках.
22. **Бюджет времени включает разминку**: 5 мин общая + 3 мин мобильность + 3 разминочных подхода × 1,5 мин (если есть базовое упражнение). Длительность упражнения = подходы × (время подхода 45/35 с + отдых 150/90 с для базового/изолирующего). Отдых после последнего подхода тоже учитывается — это запас на переход между снарядами.
23. **Недельный объём** = рабочие подходы завершённых тренировок текущей недели (пн–вс) + план текущей тренировки. Вспомогательная мышца получает половину подхода (настраивается).
24. **Порядок**: при добавлении базовое упражнение встаёт после последнего базового, изолирующее — в конец. Пользователь может переставить вручную.

## Прогрессия и аналитика

25. **Двойная прогрессия** оценивается по подходам с максимальным весом последней тренировки: все на верхней границе диапазона — повысить вес на шаг снаряда (штанга 2,5, гантели 2, тренажёр 5, блок 2,5 кг); есть подходы ниже нижней границы — держать вес; иначе добавлять повторения.
26. **Стагнация**: в последних N тренировках упражнения (N = 3, настраивается) лучший расчётный 1ПМ не превысил прежний максимум. Рекомендация — разгрузочная неделя (−10–15 % веса, вдвое меньше подходов) или смена варианта.
27. **1ПМ по Эпли** w × (1 + r/30); при r = 1 — сам вес. В интерфейсе пометка, что это ориентир с погрешностью после 10 повторений.
28. **Недогруженные группы** оцениваются по последней полной неделе (текущая обычно ещё не закончена), на главной показывается прогресс текущей недели.
29. **Поиск в каталоге** выполняется в PHP (`mb_stripos`) — регистронезависимо для кириллицы в любой СУБД; каталог небольшой.

## Интерфейс

30. **Таймеры на клиенте** (Alpine): общий считает от `started_at`, таймер отдыха запускается событием Livewire после записи подхода и хранит время окончания в `localStorage`.
31. **Перенос тренировки** — полем даты в настройках тренировки, без drag-and-drop: на телефоне это надёжнее.
32. **Иконки** — 27 собственных простых SVG по типам движения; неизвестный ключ показывает иконку по умолчанию (гантель).
33. **PWA** — только манифест и иконки, без service worker (офлайн по ТЗ не нужен).
34. **Защита от N+1**: `Model::preventLazyLoading()` вне продакшена — тесты падают при ленивой загрузке связей.
